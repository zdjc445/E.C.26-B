# 分层状态与记忆

## 追问：长期记忆在哪里写入？

> 长期记忆和任务 Checkpoint 是两套持久化。Memory Prepare 只根据 Intent 结果生成待写入的
> `MemoryMutation`；用户确认后，Supervisor 为当前 mutations 生成绑定内容哈希的授权。Memory
> Commit 校验 owner、授权和 mutation 哈希后调用 `MemoryPort.commit()`，最终由 SQLite 或
> PostgreSQL Memory Adapter 写入 `user_memory`。

执行链路是：

```text
Intent 产生记忆指令
  → Memory Prepare 生成 Mutation
  → 用户确认
  → Supervisor 绑定授权
  → Memory Commit 校验并写入数据库
```

## 追问：如何保证重复恢复不会重复写入？

> 第一层由任务 Checkpoint 保证：恢复后已经完成的 Memory Commit 不会再次派发。第二层由 Memory
> Adapter 保证：`memory_mutation` 表以稳定的 `mutation_id` 记录载荷哈希，相同变更重复提交时直接
> 跳过，ID 相同但内容不同则报冲突。测试会重复提交同一份恢复请求，并断言 `Memory.commit()` 的
> 调用次数仍然是一次。

- 记忆任务生成：`src/shijiajing_agent/multi_agent/planner.py` 中的 Memory Prepare/Commit 建图逻辑
- 用户确认与授权：`src/shijiajing_agent/multi_agent/supervisor.py` 中的 `memory_confirmation` 处理
- 授权校验与提交：`src/shijiajing_agent/multi_agent/agents/memory.py` 中的 `MemoryAgent.execute()`
- SQLite/PostgreSQL 写入：`src/shijiajing_agent/adapters/memory.py`
- 重复恢复测试：`tests/multi_agent/test_supervisor.py` 中的
  `test_multi_agent_memory_confirmation_has_single_authorized_commit()`
