# 识价镜 Agent：项目整体讲解

> 用途：面试开场时完整介绍项目，并为后续四个技术亮点建立统一上下文。
> 本文以当前代码和简历表述为准；四个专项问题分别在 `01`～`04` 文档中展开。

## 1. 讲解主线

整体介绍不要从框架名开始，而应按照下面的顺序展开：

1. 先说明要解决的业务问题；
2. 再说明普通单链 Agent 为什么不够；
3. 用一条端到端链路讲清系统怎么工作；
4. 提炼四个最有代表性的技术难点；
5. 最后说明工程化验证、当前边界和自己的工作。

项目的核心不是让多个 LLM 互相聊天，而是：

> 把图片和自然语言中的非结构化理解，转化为可执行的购物约束，并在跨平台商品表达不一致的情况下完成召回、同款判断、SKU 拆分和可信比价。

## 2. 一句话介绍

识价镜是一个面向图片或自然语言输入的商品识别与智能比价 Agent：系统通过受控的层级式
Multi-Agent 编排识别、意图、检索、解释和记忆能力，完成跨平台商品召回、同款判断、SKU
拆分、确定性排序与证据校验，最终输出可以追溯到结构化商品证据的比价结果。

## 3. 30 秒版本

> 我做的项目叫识价镜，是一个支持图片和自然语言输入的商品识别与比价 Agent。用户可以上传
> 商品图片，或者直接描述品牌、型号、预算和偏好；系统先并行完成商品识别与意图理解，再通过
> Dense、Sparse 和元数据混合召回候选商品，之后进行跨平台商品归一化、同款判断、SKU 拆分和
> 确定性排序。整个系统默认由 Supervisor 按类型化任务 DAG 调度五类专业 Agent，并通过
> 确定性计划门禁、用户硬过滤和结构化证据约束控制模型参与业务决策的范围。

适用场景：面试官只要求“简单介绍一下项目”时使用。说完后停下来，等待对方选择感兴趣的方向。

## 4. 2 分钟标准讲解稿

### Part 1：项目定位与业务问题（约 20 秒）

> 我做的项目叫识价镜，它是一个支持图片和自然语言输入的商品识别与智能比价 Agent。
> 这个项目想解决的并不只是“识别图片里是什么商品”，而是识别之后如何在多个平台召回候选、
> 统一不同平台的商品表达，判断是不是同一个商品和同一个 SKU，并给出有证据支撑的比价结果。

### Part 2：整体架构（约 35 秒）

> 当前系统采用 Supervisor 驱动的层级式 Multi-Agent 架构。Supervisor 生成和校验带依赖、预算及
> 幂等键的类型化任务 DAG，五类 Specialist Agent 只接收当前任务的私有输入并返回类型化结果，
> 最终由 Supervisor 统一汇合。默认计划确定性生成；模型 Planner 只能提出受 allowlist 限制的
> 结构化建议，还必须经过确定性物化和计划校验。这样设计的重点不是增加 Agent 数量，而是把任务
> 依赖、数据边界、预算和控制权显式化，便于并行调度、失败重试和任务级恢复。

### Part 3：核心执行链路（约 35 秒）

> 从执行链路看，图片识别和文本意图可以并行进行，汇合后形成统一的购物约束。检索阶段先把用户
> 明确提出的品牌、型号、预算、平台等条件固化为硬过滤，再执行 Dense、Sparse 和元数据混合召回。
> 候选商品会经过归一化、硬冲突否决和 Complete-Link 同款聚类，然后按照颜色、容量、套装等
> variant 属性拆分 SKU。价格聚合和最终排序都是确定性代码，不交给 LLM。

### Part 4：四个技术亮点（约 30 秒）

> 项目中我重点解决了四个问题：第一是受控 Multi-Agent 的任务隔离、依赖调度和计划门禁；
> 第二是通过局部 Schema 发现与字段归一化处理未知品类；第三是用硬过滤和结构化证据约束 RAG
> 与生成解释；第四是区分本轮状态、会话上下文和跨会话长期记忆，并通过 owner、scope、HITL
> 和稳定 mutation_id 防止越权或重复写入。

### Part 5：工程化设计与项目边界（约 10 秒）

> 工程上，模型、检索、Checkpoint、Memory、Cache 和可观测能力都通过 Port/Adapter 注入；
> 同时提供幂等请求账本、事件审计、离线评测和 fail-closed 发布门禁。仓库当前重点是
> Agent 逻辑和工程化能力，不包含 Web API 与客户端。
