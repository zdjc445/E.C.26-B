# 识价镜 Agent：项目整体讲解

> 用途：面试开场介绍当前实现。旧的 Supervisor/DAG 方案已经归档，不是生产运行入口。

## 1. 一句话介绍

识价镜是一个支持图片和自然语言输入的商品识别与比价 Agent：它把非结构化输入转换成购物
约束，经混合召回、动态归一化、同款判断、SKU 拆分和确定性排序，输出带结构化证据的比价结果。

## 2. 30 秒版本

> 用户可以上传商品图片，或直接描述品牌、型号、预算和偏好。系统先完成识别与意图理解，
> 然后通过 Dense、Sparse 和元数据召回原始 Offer；候选经过动态局部 Schema、硬约束三态校验、
> Complete-Link 同款聚类和 SKU 拆分后再排序。生产只有 `AgentFacade → MainAgentRuntime` 一条
> 执行链：主 Agent 每轮提出一个严格动作，普通请求可以零次委派，只有存在明确检索缺口或
> 详情争议时才启动受限 Research/Verification subagent。

## 3. 当前执行结构

```text
请求/恢复 → AgentFacade → 准备识别、意图与会话上下文
                         ↓
                 MainAgent observe/decide
                         ↓ 一个严格动作
       检索比较 / 补充检索 / 证据读取 / 按需委派 / 追问 / 回答
                         ↓
              运行时校验 → checkpoint → 再观察
```

主 Agent 不能直接写商品组、硬约束、长期记忆或任意 URL。runtime 负责动作目录、版本、证据、
预算、幂等和副作用授权；子 Agent 只接收冻结约束与有限候选/证据，结果返回后还要由父 runtime
重新校验。

## 4. 商品处理链

```text
原始 Offer 保真
  → 单一 raw search text
  → 有界混合召回
  → 动态局部 Schema / 通用基线
  → 需求 satisfied / conflict / unknown 校验
  → Complete-Link 同款
  → SKU 拆分
  → 价格与偏好排序
  → 证据约束回答
```

用户硬约束始终在召回后复核；未知不算满足，商品概要不能冒充真实 SKU 报价。Dense、Sparse、
本地词法降级和索引发布都绑定 `IndexManifest`，查询 fingerprint 也包含 manifest 身份。

## 5. 工程边界

- `domain/` 保存约束、动态 Schema、同款、SKU、排序等纯逻辑；`services/` 组合业务能力；
  `agent_runtime/` 是规范状态唯一写入者；`adapters/` 实现外部端口。
- `agent-runtime-v2` checkpoint 保存有界结构化状态，不保存用户全文、图片 data URL、Prompt
  或模型原始响应；Request Ledger 以 `(session_id, request_id)` 保证幂等。
- runtime 分开记录逻辑检索、数据库搜索尝试和 embedding 调用，并在批量动作前预留物理预算。
- 真实 Milvus、embedding、平台快照和线上延迟仍需部署环境证据；仓库 seed/Fake 只证明契约和
  确定性边界，不代表真实平台核验。
