# 分层状态与长期记忆

## 1. 三类边界

以“记住以后买耳机预算 1000 元”为例，系统区分：

| 类型 | 当前实现 | 生命周期 | 用途 |
|---|---|---|---|
| 本轮状态 | `MainRuntimeState` | 一个 turn，可由 checkpoint 恢复 | 动作、查询、候选、证据、预算和中断 |
| 会话摘要 | `recent_turns` | 当前会话的有界窗口 | 多轮指代和近期约束 |
| 长期记忆 | `MemoryPort` | 跨会话、按 owner 隔离 | 用户明确授权的偏好或默认约束 |

这三类数据不能混成一份“聊天历史”。本轮用户明确说预算 800 元时，必须覆盖长期记忆中的
1000 元；只有本轮没有明确值时，已确认记忆才能作为默认约束。

## 2. 读取链路

```text
识别/意图结果 → MainRuntime 构造 MemoryQuery
              → Memory Service 按 owner、scope 召回
              → 运行时按 apply_mode 合并
              → 形成当前请求约束与排序上下文
```

`memory_owner_id` 必须来自可信调用上下文，不能从用户文本或请求 metadata 指定。记忆使用
`scope_key` 隔离 global 与品类范围，并通过 `constraint_default`、`ranking_preference`、
`negative_term` 控制作用；它不能绕过当前请求硬约束。

## 3. 写入链路

长期记忆固定经过 `prepare → confirm → commit`：

1. Intent Service 从用户明确表达生成 `MemoryDirective`；
2. Memory Service 校验字段白名单、值域、owner、scope 和应用方式，生成稳定 `MemoryMutation`；
3. runtime 保存 mutation ID 和 payload hash，启用 HITL 时创建确认中断；
4. 恢复时校验 interrupt ID、授权 ID、mutation 列表和 payload hash；
5. 通过校验后才提交，重复 resume 按 mutation ID 幂等处理。

没有明确“记住/保存”等授权语义的普通偏好不能写入长期记忆。Commit 失败时不能返回“已记住”。

## 4. 恢复与故障

- `agent-runtime-v2` checkpoint 是本轮结构化状态的事实源，不保存用户全文、图片 data URL、
  Prompt、密钥或模型原始响应。
- 已完成的只读动作和 Memory mutation 可复用；未提交只读子任务只能在剩余预算内有限重跑。
- recall 故障可以让比价继续，但必须标记历史偏好未应用；prepare 失败不生成 mutation；commit
  失败明确返回未保存。
- owner 越权、非法字段、伪造授权和 payload 冲突都以能力拒绝或固定错误结束。
