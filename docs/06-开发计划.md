# 开发计划

## 迭代原则

- 以 API 契约为主线推进开发
- 第一轮以 Web/PWA + Spring Boot + PostgreSQL/Flyway 作为可运行交付，Flutter 作为后续移动端路线
- 先完成 mock 数据闭环，再替换真实数据源
- 每个版本都应该能运行、能演示、能解释
- 用户私有数据从第一版开始做隔离，不能后补

## 主流程

```text
imageId -> recognitionId -> searchTaskId -> comparisonId -> recommendationId
```

## 版本规划

| 版本 | 目标 | 主要功能 | 验收产物 |
| --- | --- | --- | --- |
| v0.1 | 项目骨架与认证 | Flutter 工程、Spring Boot 4 工程、PostgreSQL/Flyway、注册登录、Token 刷新、当前用户接口 | 能注册登录并访问受保护接口 |
| v0.2 | 图片与识别 | 图片上传、图片列表、识别任务、低置信度提示 | 能得到 `imageId` 和 `recognitionId` |
| v0.3 | 搜索任务与 mock 商品库 | 创建搜索任务、mock 平台商品、搜索历史、候选结果 | 能得到 `searchTaskId` 和候选 `platformProductId` |
| v0.4 | 比价与历史价格 | 创建比价、价格排序、平台商品详情、历史价格趋势 | 能得到 `comparisonId` 并展示价格趋势 |
| v0.5 | Agent 推荐与 evidence | 基于 `searchTaskId` 和 `candidateIds` 生成推荐、理由、风险和证据链 | 能得到 `recommendationId` 和 `evidence` |
| v0.6 | 收藏与价格提醒 | 收藏商品、收藏列表、价格提醒预留接口 | 用户收藏和提醒数据隔离 |
| v0.7 | 演示优化 | 示例数据、演示脚本、异常场景兜底、UI 优化 | 能稳定演示完整购物决策闭环 |

## 优先级

高优先级：

- 用户认证与数据隔离
- 图片上传与识别
- 搜索任务和 mock 商品候选
- 比价和历史价格
- Agent 推荐与 evidence 证据链

中优先级：

- 评价摘要
- 收藏
- 价格提醒接口
- 推荐记录查询

低优先级：

- 更多真实官方 API 平台接入
- 授权样例数据适配器
- 用户画像
- 自动购买

## MVP 数据策略

MVP 阶段固定使用 `mock` 数据源：

- mock 商品库覆盖手机、耳机、吹风机、键盘、水杯、运动鞋、护肤品
- mock 价格历史用于趋势图和 Agent 证据链
- mock 评价摘要用于风险提示
- `official_api` 已接入拼多多/京东开放平台适配器，继续扩展时保持前端 API 不变，不做非授权数据抓取

## 固定技术栈

```text
frontend: Web/PWA first, Flutter + Dart + Dio + Riverpod + fl_chart later
backend: Spring Boot + Java 21 + Spring Security
database: PostgreSQL + Flyway
api docs: springdoc-openapi
storage: local uploads/
mock: MockRecognitionProvider + MockProductSourceProvider
agent: RuleBasedRecommendationService
```
