## 协作边界

- `docs/00-比赛要求.md` 作为赛事要求归档，原则上只补充整理，不改写要求本身。
- 前端不接触 Ark、拼多多、京东等密钥；所有密钥只通过服务端环境变量或本地 `.env` 注入。
- 价格、评分、评价、历史低价等事实必须来自后端数据源，不能由 LLM 或前端临时编造。
- 默认演示使用 `mock` 数据，真实平台只通过 `official_api` 适配器和授权开放平台 API，不做爬虫。
- 如果录屏或答辩展示真实凭证、请求日志、平台页面，必须遮挡密钥、Token、签名和个人账号信息。

## 答辩追问准备

| 追问方向 | 回答要点 |
| --- | --- |
| 为什么使用 mock 数据 | 比赛允许合法 mock；本项目重点证明链路、架构和 Agent 决策可解释性，同时保留官方 API 适配器 |
| AI 在哪里发挥作用 | VLM 识别、LLM refine、Prompt 结构化输出、fallback 调度、代码开发辅助；最终价格决策由服务端证据计算 |
| 如何避免幻觉 | Prompt 限定 JSON 字段，FilterSanitizer 白名单校验，价格/评价/历史走势只读后端数据 |
| 如何证明能跑 | 后端 `mvn test`、Web Selenium smoke test、PWA cache 断言、官方 API live smoke 脚本 |
| 为什么有技术深度 | 服务端编排、多源数据适配、用户隔离、决策信号、决策轨迹、候选胜因/败因矩阵、PWA 运行韧性 |
