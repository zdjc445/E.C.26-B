# 答辩材料

本文档面向 30 分钟答辩流程（5 分钟演示 + 10 分钟设计讲解 + 15 分钟评委问答）准备的速查材料。配合 [00-比赛要求.md](00-比赛要求.md)、[09-演示脚本.md](09-演示脚本.md) 与 [10-AI使用总结.md](10-AI使用总结.md) 使用。

## 5 分钟演示要点

按 [09-演示脚本.md](09-演示脚本.md) 中 Step 0 → Step 7 顺序执行。重点演示三条主链路：

1. **拍照识物：** 拍照 → 带识别元数据的商品分组卡 → 动态建议卡（6 个差异化选项）。
2. **导购建议：** 商品分组卡显示最低价、价格区间、平台报价明细、命中偏好和价格走势。
3. **自然语言追加筛选：** 单句覆盖品类、预算、颜色、品牌、平台、排序、最低评分，多轮跨上下文合并。

## 10 分钟设计讲解大纲

### 1. 项目定位（1 分钟）

- 聊天式购物 Agent，前端 Flutter Android，后端 Spring Boot Java 21。
- 目标：用 Mock 闭环 + Ark AI 增强，验证「拍照识物 → 动态建议 → 自然语言筛选 → 比价推荐」端到端可行性。

### 2. 整体架构（2 分钟）

参考 [02-系统架构草案.md](02-系统架构草案.md)。
- 客户端：聊天首页 + 历史抽屉 + 我的页面。
- 服务端：`api` 控制器 / `chat` Mock Agent / `ai` 识别 Provider / `product` 商品源与解释器 / `image` 上传与存储。
- 数据：内存仓库；上传文件落盘 `uploads/`；Postgres 留作后续迭代。

### 3. AI Pipeline 编排（3 分钟）

- 三条 Provider 链路：识别 / 意图解析 / 推荐解释，全部走「规则默认 + Ark 增强 + 失败回退」三段式。
- 详见 [10-AI使用总结.md](10-AI使用总结.md) 第 1、2 节。
- 强调 Prompt 设计的几点：枚举字段封顶、JSON Schema 兜底、白名单字段拦截、结构化字段不允许 AI 改写。

### 4. 模块可扩展性（2 分钟）

- AI Provider 可插拔：实现 `AiRecognitionProvider` / `ShoppingIntentParser` 接口即可替换。
- 商品源可切换：默认 `public-dataset-platforms` 读取公开样例商品并生成四平台样例报价；`mock-data` 仍保留为本地演示和回归测试源。
- 品类归一可替换：当前使用轻量 taxonomy 检索，真实上线可替换为 RAG 召回和受限选择。
- UI 卡片驱动：后端只输出 `cardType + 字段`，前端按 `_buildCard` switch 渲染，新增卡片只需扩展枚举。

### 5. 鲁棒性与回退（1 分钟）

- 回退矩阵参考 [10-AI使用总结.md](10-AI使用总结.md) 第 3 节。
- 演示「关掉 Ark Key → Provider 徽章变红 → notices 文案出现」。

### 6. 测试与验收（1 分钟）

- 后端 142 条 JUnit 用例，覆盖意图解析、品类归一、多轮合并、品牌/平台/排序/最低评分筛选、筛选摘要收口、Ark 回退、识别修正。
- Flutter 37 条 widget 测试，覆盖用户记忆、`profile` 参数、商品分组、历史恢复、识别修正面板、动态建议选项、品牌徽章、底部输入框和商品详情页。

## 15 分钟评委问答速查

> 每个问题都标注了负责模块，详见 [11-项目分工说明.md](11-项目分工说明.md)。

### Q1. 你们的核心创新点是什么？
> 三段式 AI 编排（规则 + Ark + 回退）+ taxonomy 检索归一（细分品类映射到标准品类）+ 跨轮多维度自然语言筛选（7 维度：预算 / 颜色 / 品牌 / 平台 / 排序 / 最低评分 / 偏好倾向）+ 动态建议卡（按识别 category 生成差异化选项）。

### Q2. 综合分是怎么算的？
> `RecommendationExplainer.weightedScore`：意图匹配 25% + 价格 25% + 店铺信誉 20% + 渠道可信 15% + 风险 15%。每个维度都有独立计算函数，可单测、可解释。

### Q3. Ark 失败时怎么保证不挂？
> 三级回退：
> 1. `ArkClient.enabled=false` 直接抛 IllegalStateException。
> 2. `FallbackShoppingIntentParser` / `FallbackRecognitionProvider` / `ArkRecommendationExplainer.explain` catch 异常并回退规则结果。
> 3. UI 通过 `intentFallbackUsed` / `explanationFallbackUsed` 徽章与 `notices` 文案让用户/评委感知。

### Q4. 多轮筛选怎么记上下文？
> `MockAgent.mergeContext` 扫描会话历史，按字段维度处理：
> - 品类：当前明确 > 历史明确 > 历史识别 category > 默认运动鞋；进入推荐前统一经过 `CategoryResolver` 归一。
> - 数值字段（maxPrice/color/brand/平台/排序/最低评分）：当前明确值覆盖历史最新值。
> - 偏好布尔（officialStore/fastDelivery/lowestPrice/highRating/highSales）：跨轮累积。

### Q5. 商品 ID / 价格会被 AI 改吗？
> 不会。`ArkRecommendationExplainer.rewriteAnalyses` 始终使用规则结果的 `productId / platform / title / rank / score`，Ark 返回的 productId 直接丢弃。已被 `rewriteAnalysesShouldPreserveOriginalProductIds` 测试覆盖。

### Q6. 平台名怎么避免错位？
> 平台值经过代码白名单校验，当前后端报价平台为 `京东-mock / 拼多多-mock / 淘宝-mock / 天猫-mock`。商品本身的 `platform` 字段由 `CompositeProductSourceProvider` 生成，Ark 无权改写。

### Q7. 为什么用 Mock 而不是真实平台？
> 真实电商 API 多数没有合规的公开实时接口，而且实时接口会带来登录、风控、库存和价格波动。本项目重点验证 Agent 的识别、意图解析、多轮筛选、同款分组和解释能力，因此当前交付默认使用公开样例商品数据并生成四平台样例报价，不调用真实电商接口；本地 `mock-data` 可切换用于离线演示和回归测试。

### Q8. 品牌识别为什么是规则？
> 当前规则覆盖常见中英文品牌，命中即可标记。Ark 路径在 `ArkShoppingIntentParser` 中也支持品牌字段，仅当未配置 Ark 或调用失败时回退规则。商品结果取决于当前商品源。

### Q9. 用什么模型？为什么？
> 火山引擎 Doubao-Seed-2.0-lite，赛事提供专用 EP/APIKey。轻量模型适合结构化解析与文本改写场景，响应快、性价比高。Prompt 设计强制 JSON Schema 兜底，弱化对模型推理能力的依赖。

### Q10. 你们怎么用 AI 辅助编码？
> 参考 [10-AI使用总结.md](10-AI使用总结.md) 第 4 节：先给目标、再给上下文、测试先行、拆任务跑。每次改动后必须 `mvn test` 全量回归。

### Q11. 测试用例怎么设计的？
> 三层：
> - 单元测试：解析器、品类归一、商品源、解释器单测。
> - 集成测试：`ChatControllerTest` 46 条端到端，覆盖会话、消息、识别、修正、多轮筛选。
> - 回退测试：`ArkIntegrationTests` 12 条专门验证 Ark 未配置/失败时的回退行为。

### Q12. 后续怎么扩展？
> [08-后续迭代清单.md](08-后续迭代清单.md) 已列出：Postgres 持久化生产化、账号体系完善、收藏 / 价格提醒生产化、真实语音识别、Android 打包指南。

### Q13. UI 上的「预算命中」「品牌命中」徽章怎么生成？
> `RecommendationScorer` 在打分时把命中的偏好写入 `ProductOffer.matchedPreferences`，Flutter 端 `_matchBadge` 渲染。徽章 key 包括 `low_price / official_store / fast_delivery / high_rating / high_sales / budget_match / brand_match / min_rating_met`。

### Q14. 价格走势怎么画的？
> `ProductOffer.priceHistory` 由 `defaultPriceHistory` 基于原价和当前价生成 5 点近期走势（仅作演示，不代表真实价格历史）。Flutter `_PriceSparkline extends CustomPainter` 用 Path 绘制，加上 ↑/↓ 百分比标签。

### Q15. 动态建议卡和原始三选项的区别？
> 原始固定三选项「价格最低 / 官方店铺 / 配送更快」。新版根据识别 category 动态扩展：
> - 运动鞋 → 相似风格推荐、筛选颜色/品牌/尺码。
> - 耳机 → 降噪款优先、好评率优先。
> - 吹风机 → 大功率优先、便携折叠款。
> - 背包 → 大容量款、商务款。
> - 智能手表 → 长续航款、运动款（taxonomy 和建议入口保留，是否返回商品取决于当前商品源）。
> - 识别到品牌时额外加「只看 {品牌}」。
> - 始终带「查看历史价格走势」入口。
