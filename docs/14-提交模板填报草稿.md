## 项目概述

### 项目简介

识价镜是一款聊天式购物 Agent。用户可以通过文字、图片或语音描述购物需求，系统自动识别商品类别、抽取预算/品牌/平台/评分等筛选条件，并生成跨平台样例比价、购买判断和后续筛选建议。

### 核心功能

- 拍照识物：上传图片后生成结构化识别结果，包含品类、品牌、型号、关键词、置信度和解释。
- 智能比价：基于公开数据集中的 243 个商品生成四个平台演示报价，按同款商品分组展示最低价和价格区间。
- 自然语言筛选：支持品类、预算、颜色、品牌、平台、排序、最低评分、低价/好评/销量等偏好表达。
- 多轮上下文：用户可以连续说“只看京东”“评分 4.8 以上”“价格从低到高”，系统会继承上一轮品类和已明确条件。
- 动态建议卡：根据品类生成差异化建议，例如耳机的“降噪款优先 / 好评率优先”、运动鞋的“相似风格推荐 / 筛选颜色品牌尺码”。
- 商品详情页：整理购买判断、评价概览、平台比价、精选评论、价格走势、收藏和价格提醒。
- 用户侧能力：支持简易认证、收藏商品、价格提醒、历史会话恢复、语音转写入口。

### 亮点与创新点

- 三段式 AI 编排：规则默认 + Ark 增强 + 失败回退，保证演示稳定，同时保留 AI 识别和解释增强能力。
- 结构化字段安全边界：商品 ID、价格、平台、排序和分数由代码控制，AI 只参与识别、意图解析和解释文本改写，降低幻觉风险。
- Taxonomy 归一：将“真无线蓝牙耳机”“跑鞋”“电吹风”等细分说法归一到标准品类，提升自然语言输入容错。
- 同款分组比价：同一公开样例商品在运行时扩展为四个平台演示报价，前端以商品组展示平台差价和最低价。
- 可解释购买判断：详情页按最低价、评分、评价量、平台差价和服务标签给出清晰购买建议。

### 目录结构与启动说明

```text
backend/     Spring Boot API 服务
app/         Flutter Android 客户端
docs/        项目文档
mock-data/   可切换本地样例数据
scripts/     辅助脚本
uploads/     本地上传文件目录
```

后端启动：

```powershell
cd backend
mvn test
mvn -DskipTests clean package
java -jar target/price-lens-0.1.0.jar
```

Flutter 真机启动：

```powershell
adb reverse tcp:8080 tcp:8080
cd app
C:\flutter\flutter\bin\flutter.bat run -d <device-id> --dart-define=EC26B_API_BASE_URL=http://127.0.0.1:8080
```

Flutter 模拟器启动：

```powershell
cd app
C:\flutter\flutter\bin\flutter.bat pub get
C:\flutter\flutter\bin\flutter.bat run -d emulator-5554 --dart-define=EC26B_API_BASE_URL=http://10.0.2.2:8080
```

### 安装包

当前本地已有 Debug APK：

```text

```

最终提交建议补一个 Release APK：

```powershell

生成路径：

```

## 项目总结 / 自评 / 补充

### 对照课题总结

识价镜围绕“AI 拍照识物与智能比价购物助手”完成了端到端闭环：图片识别、聊天式导购、自然语言筛选、同款分组、跨平台样例比价、商品详情决策、收藏和价格提醒。系统通过 Spring Boot 后端输出结构化卡片，由 Flutter 端统一渲染，评委可以在真机上完整体验从输入需求到对比平台再到收藏提醒的主流程。

### 已完成度

- 后端：142 条测试通过，覆盖会话、识别、意图解析、公开商品源、Ark 回退、收藏和价格提醒。
- 前端：Flutter test 运行器通过 41 条测试，其中 37 条 widget 测试覆盖聊天首页、商品分组、筛选编辑、收藏、详情页和价格提醒，4 条模型解析测试覆盖卡片、平台报价和电商状态字段。
- 真机验证：已在 Android 真机通过 USB 调试完成 8080 后端联调。

### 难点与解决思路

- 难点 1：AI 输出不稳定。解决：结构化字段由规则代码控制，Ark 只做增强；失败时统一回退，并通过状态字段透传。
- 难点 2：自然语言筛选跨轮合并。解决：会话历史按字段维度合并，当前明确值覆盖历史值，偏好布尔项累积。
- 难点 3：没有真实电商公开接口。解决：从公开数据集的 20,000 行 CSV 中确定性筛出 243 个基础商品，由代码生成四平台演示报价，并明确评分、销量、品牌和图片外链的数据边界。
- 难点 4：移动端卡片信息密度高。解决：商品结果页和详情页按“结论优先、详情后置”重新组织，真机截图验证布局。

### 不足与后续计划

- 当前平台报价为样例数据，不代表真实平台库存和价格。
- Release APK 需要根据评委体验环境配置后端地址。
- 真实语音识别和真实电商 API 接入仍需后续完善。
- 生产环境需要完善正式账号体系、权限、数据持久化、日志审计和隐私合规说明。
