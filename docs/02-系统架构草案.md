# 系统架构草案

## 整体架构

```text
┌─────────────────────────────┐
│   Flutter Android Client    │
│  Chat UI / Image Picker     │
│  Clarification / Recommend  │
└─────────────┬───────────────┘
              │ REST / JSON / Multipart
              ▼
┌─────────────────────────────┐
│   Spring Boot API Server    │
│  Chat / Upload / Health     │
└──────┬──────────┬───────────┘
       │          │
       ▼          ▼
┌──────────┐ ┌──────────────┐
│ Mock     │ │ Local Upload │
│ Agent    │ │ Storage      │
└──────────┘ └──────────────┘
```

## 技术选型

| 层级 | 技术 | 说明 |
|------|------|------|
| 客户端框架 | Flutter 3.22+ | Android 平台 |
| 状态管理 | Riverpod | 聊天状态与接口调用状态 |
| 路由 | GoRouter | 声明式路由 |
| 图片选择 | image_picker | 相册选图 |
| HTTP 调用 | http | REST 与 multipart 请求 |
| 服务端框架 | Spring Boot 3.4 | Java 21 |
| 构建工具 | Maven | 依赖与构建管理 |
| 当前 Agent | Mock Agent | 固定追问与推荐卡片 |
| 后续 AI 模型 | 火山引擎 Doubao | 通过 Ark API 调用 |
| 数据格式 | JSON | REST API 契约 |

## 当前阶段架构约束

- 首页以聊天式 Agent 作为主入口
- 图片上传保存到本地 `uploads/`
- 聊天会话和上传元数据使用内存结构
- Mock Agent 只返回固定追问卡片和推荐卡片
- 无数据库依赖，后续引入 Postgres
- 无认证层，后续引入 Spring Security 与 JWT
- 前后端通过 REST API 通信，本阶段不使用 SSE 或 WebSocket
