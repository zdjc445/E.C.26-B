# 分层上下文与记忆管理 — 图片内容

## 图 1：四层上下文与记忆

- 标题：四层记忆，各自解决不同时间尺度的问题
- 布局：四层阶梯或同心层，按 L1 → L2 → L3 → L4 展开
- L1 近期原始对话：
  - 内容：最近的用户与助手原始消息
  - 生命周期：短期、按 Token 淘汰、强制 TTL
  - 用途：理解“这台 iPhone”“第二款”“改成 256GB”等指代和修正
- L2 中期工作上下文：
  - 内容：当前主题的目标、有效约束、候选取舍、缺口、冲突和未解决问题
  - 生命周期：主题活动期间，确定性规则裁剪
  - 用途：维持一次购物任务的连续状态
- L3 远期主题摘要：
  - 内容：旧主题的目标、最终约束、选择结果、证据引用和未解决项
  - 生命周期：中长期，按相关性最多召回 3 个主题
  - 用途：恢复“上次比较的那两款 iPhone”
- L4 长期用户画像：
  - 内容：跨主题稳定偏好，区分 `explicit / inferred`
  - 生命周期：跨会话，支持冲突、衰减、过期和删除
  - 用途：补充默认值或排序先验
- 优先级条：本轮明确输入 > 当前主题用户锁定值 > 显式长期默认值 > 推断画像排序先验

## 图 2：从 L1 对话到 L2 状态，再到 L3 摘要

- 标题：原话留在 L1，有效状态同步进入 L2，旧任务再压缩到 L3
- 布局：左侧模拟聊天界面，中部 L2 状态卡，右侧 L3 归档卡；用时间箭头串联
- 左侧 L1 聊天气泡：
  - 用户：「帮我比较 iPhone 15 Pro 256GB 和 512GB」
  - 助手：「找到两款，第二款容量更大，但价格更高」
  - 用户：「保留第二款，预算提高到 8000」
- L1 → L2 的时机：每轮产生有效约束、候选选择、修正或新缺口后立即更新；不是等 L1 过期时才整段搬运
- 转入 L2 的内容：当前目标、规范约束、选中 / 排除的候选 ID、未解决问题、缺口和证据引用
- L2 状态卡示例：`iPhone 15 Pro / 512GB / 预算 ≤ 8000 / accepted=candidate_02 / 待确认颜色`
- L2 → L3 的时机：当前购物任务结束或切换、L1 即将淘汰、L2 过长，或会话关闭
- 转换后的状态：
  - L2：旧任务冻结并短期保留；当前会话只继续维护仍活跃任务的详细状态
  - L3：保存旧任务的目标、最终约束、选择结果、未解决项和证据 ID，并生成一段短摘要

## 图 3：L3 主题摘要的生成与召回

- 标题：旧 iPhone 任务被压缩保存，需要时再按相关性找回
- 左侧生成：冻结的 L2 → 规则提取结构化事实 → `DeepSeek-V4-Flash` 生成短摘要 → 引用校验 → L3
- L3 卡片示例：
  - 目标：`为自己选择 iPhone 15 Pro`
  - 最终约束：`512GB / 预算 ≤ 8000`
  - 决策：`保留 candidate_02，颜色待确认`
  - 证据：`evidence_12 / evidence_18`
- 右侧召回：用户说「继续上次那两款 iPhone」→ 按用户、品类和主题状态过滤 → 关键词 / 向量相关性排序 → 最多返回 3 个 L3 摘要
- 恢复结果：根据摘要引用重新加载结构化约束，本轮新输入仍拥有最高优先级

## 图 4：L4 长期用户画像

- 标题：明确记忆可作默认值，推断记忆只能影响排序
- 左栏「显式画像」：
  - 用户：「以后买 iPhone 默认预算 7000 元」
  - Intent 生成候选 directive → 服务端校验 → 用户确认 → 写入 `constraint_default`
- 中栏「推断画像」：
  - 只采纳用户明确选择、拒绝或反馈
  - 至少 3 次观察，覆盖 2 个主题和 2 个会话，置信度达到 0.80
  - 只写入 `ranking_prior / negative_preference`
- 右栏「应用冲突」：画像默认预算 7000；本轮用户说「这次买 iPhone 预算 8000」→ 使用 8000
- 底部状态流：`pending → active → superseded / forgotten / expired`

## 图 5：DeepSeek-V4-Flash 的上下文预算

- 标题：模型支持 1M 上下文，应用常态只装到约 64K
- 布局：一个 64K 堆叠条，旁边注明“1M 是模型物理上限，不是每次都填满”
- 64K 应用预算按整数 K 展示：
  - 推理与输出预留：约 16K
  - System、工具 Schema、协议和安全余量：约 8K
  - 可用业务上下文：约 40K
- 40K 业务上下文示例：
  - 当前请求与有效约束：约 6K
  - 候选与证据：约 16K
  - L1 近期消息：约 8K
  - L2 工作上下文：约 4K
  - L3 主题摘要：约 3K
  - L4 已应用画像：约 1K
  - 动态共享余量：约 2K
- 动态借用：没有候选的澄清轮把额度借给 L1；需要核验 iPhone 规格时把空闲额度借给候选与证据
- 超出 64K：先减少低相关 L3 / L4 和低排名候选，再淘汰最旧 L1；当前请求和用户锁定约束始终保留
