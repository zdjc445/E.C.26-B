# 项目范围与阶段计划

## 项目定位

本项目是一款面向 C 端消费者的 AI 拍照识物与智能比价购物助手。客户端首页采用聊天式购物 Agent 交互，用户可以通过文字或图片描述购物需求，系统通过识别、追问、比价和推荐卡片辅助用户做购买决策。

## 当前阶段：聊天式 AI 识别与多平台 Mock 推荐阶段

**目标：** 在聊天式首页下形成可演示的“文字/图片输入 → AI/Mock 识别 → 偏好追问 / 自然语言追加筛选 → 多平台 Mock 商品 → 比价 → 推荐”的闭环。

**已完成能力：**

- Spring Boot 后端服务、健康检查和统一响应结构
- 手机 USB 调试下的核心演示闭环
- Flutter Android 聊天首页、历史入口、个人页入口和底部输入栏
- 图片上传、拍照/相册选择、本地预览
- 聊天会话创建、列表、历史读取、重命名、删除
- 图片识别接口、识别结果卡片和识别修正能力
- `MockRecognitionProvider`、`ArkRecognitionProvider`、`FallbackRecognitionProvider`
- `AI_PROVIDER=ark` 配置路径，Ark 不可用时回退 Mock
- `RuleBasedShoppingIntentParser`、`ArkShoppingIntentParser`、`FallbackShoppingIntentParser`
- 多轮自然语言追加筛选：继承历史文本品类、识别卡 category、预算、颜色和偏好
- 推荐解释增强：综合分、决策信号、证据摘要、风险提示、商品胜因/不足
- 多平台 Mock 商品数据源：`京东-mock`、`拼多多-mock`、`淘宝-mock`
- Mock 商品类别：运动鞋、耳机、吹风机
- 商品列表卡、平台比价卡、推荐购买卡
- 超预算时空商品卡和空比价卡占位
- 历史会话恢复完整 `agentReply` 卡片
- 后端与 Flutter 自动化测试覆盖核心流程

**当前边界：**

- 真实 AI 识别需要配置 Ark 后继续实测，不默认保证外部服务可用。
- Ark 购物意图解析和推荐解释改写需要配置 Ark 环境变量；未配置或调用失败时回退规则解析与规则解释。
- 商品搜索和比价来自 Mock 数据，不代表真实平台商品、价格或库存。
- 真实电商 API、真实认证、Postgres 落地、真实语音识别、收藏、价格提醒仍为后续迭代。
- 当前 Agent 输出结构化解释摘要，不输出真实模型推理链。

## 下一阶段：真实 AI 识别实测增强 + 交付材料补齐

**目标：** 在保留 Mock 降级能力的基础上，完成真实 Ark 图片识别实测记录，并补齐最终交付与答辩材料。

计划能力：

- 使用真实 Ark 配置进行多类商品图片实测
- 补充 Ark 调用失败、fallback、识别字段缺失的展示与测试
- 在已接入推荐解释字段基础上打磨展示口径和演示路径
- 增强商品卡：评分来源、偏好命中、预算命中、平台优势
- 继续扩展自然语言筛选：品牌、指定平台、排序方式和最低评分阈值
- 补齐演示脚本、演示视频、AI 使用总结、项目分工说明和答辩材料
