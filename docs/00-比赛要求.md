# 赛事方要求记录：AI 拍照识物与智能比价购物助手

本文档记录赛事方发布的课题要求、技术边界、AI 资源说明、TRAE IDE 模型配置方式、验收方式与答辩关注点，作为后续研发、文档补齐和演示准备的统一依据。

## 1. 课题背景

日常购物中，用户经常遇到“看到想买但难以检索”的问题。例如街头同款服饰、短视频中的数码产品，用户往往缺少品牌、款式、型号等关键检索信息；即使使用截图或以图搜图，也可能出现匹配不准、结果过多、跨平台比价成本高等情况。

本课题希望通过 AI 技术打通“识别 - 检索 - 决策”链路，构建一款面向 C 端消费者的 AI 拍照识物与智能比价购物助手。用户完成一次拍摄后，系统识别商品并聚合多平台推荐结果，同时支持自然语言追加筛选，帮助用户快速收敛候选商品并完成购买决策。

项目重点包括：

- 使用 VLM 视觉模型解析图片中的非结构化商品信息。
- 使用 LLM 编排与 Prompt 工程完成意图理解、结构化输出和任务调度。
- 缩短用户从“产生购买意愿”到“完成消费决策”的路径。
- 打造流畅、可解释、可扩展的智能化购物体验。

## 2. 项目目标

实现一款面向 C 端消费者的 AI 拍照识物购物助手：

1. 客户端通过摄像头采集商品图像并上传服务端。
2. 服务端识别商品类目和关键属性，如款式、颜色、品牌、型号等。
3. 系统动态生成下一步决策建议卡片，如“查看同款低价”“只看旗舰店”“相似爆款推荐”等。
4. 用户点击建议卡片后，系统跨平台匹配相似商品并输出推荐列表。
5. 用户可通过自然语言追加筛选条件，购物助手实时刷新推荐结果。

## 3. 核心功能要求

### 3.1 拍照识物

- 支持通过 App 内相机拍摄商品。
- 上传图片到服务端，所有 AI 计算在云端完成。
- 输出识别结果，至少包含：
  - 主要类目
  - 关键属性，如品牌、颜色、款式、尺码、型号等
  - 识别置信度或候选解释
- 基于识别关键词跨平台召回相似商品，生成推荐列表。
- 支持用户修正识别错误的关键属性，例如将“蓝色”修正为“深蓝色”。

### 3.2 智能建议卡片

识别结果下方需要动态生成一组可交互建议卡片，引导用户进入下一步购买决策。

建议卡片示例：

- 查看同款低价
- 只看官方旗舰店
- 相似风格推荐
- 查看历史价格走势
- 筛选：颜色 / 品牌 / 尺码

建议卡片不应是固定按钮堆叠，最好基于识别结果、用户意图和当前商品类型动态生成。

### 3.3 跨平台比价

- 聚合多平台同款或相似商品。
- 展示每个平台的最低价。
- 展示每个平台的均价或价格区间。
- 推荐列表中体现来源平台与关键标签。
- MVP 阶段允许使用合法公开 API 或 mock 数据，不允许非法采集。

### 3.4 自然语言追加筛选

支持用户在输入框中通过自然语言追加筛选条件。

示例：

```text
帮我找 1000 元以内的黑色款，要评价 4.8 分以上的
```

系统需要解析出结构化筛选条件，例如：

- 价格上限：1000 元
- 颜色：黑色
- 评分下限：4.8

解析后实时刷新推荐列表。

### 3.5 推荐列表与排序

商品列表以卡片形式展示。每张商品卡片至少包含：

- 商品图
- 商品名称
- 商品价格
- 来源平台
- 关键标签，如“自营”“官方”“低价”“高评分”

需要支持多种排序方式：

- 综合推荐
- 价格从低到高
- 销量优先
- 好评率优先

## 5. 技术与合规边界

### 5.1 允许事项

- 可使用任意 AI 模型与 AI Coding 工具。
- 推荐使用火山引擎 OpenAPI 与 TRAE IDE。
- 可使用合法公开的电商平台 API。
- 可使用公开样例数据集。
- 在缺乏合规 API 或数据来源时，允许使用 mock 数据。
- 技术栈可根据团队熟悉度自由选择。

### 5.2 禁止事项

- 禁止使用任何端侧 AI 识别 SDK。
- 禁止在客户端本地完成商品识别 AI 计算。
- 禁止使用豆包 SDK、Google ML Kit、百度 AI SDK、阿里云视觉智能 SDK 等端侧识别能力。
- 禁止编写网络爬虫。
- 禁止以违反网站服务条款的方式获取数据。
- 禁止将比赛专用 EP、API Key 等敏感资源写入代码仓库、公开文档或提交记录。

## 7. TRAE IDE 自定义模型配置说明

以下内容来自赛事方提供的 TRAE IDE 模型配置指南，用于帮助团队成员在 TRAE 中接入比赛专用自定义大语言模型。

### 7.1 配置前准备

开始配置前，需要从指导老师或比赛平台获取以下信息：

| 配置项   | 说明                                            |
| -------- | ----------------------------------------------- |
| Endpoint | 服务商入口。本项目选择“火山引擎 - 自定义模型” |
| Model ID | 模型接入点标识，即比赛提供的 EP                 |
| API Key  | 用于身份验证的密钥                              |

注意事项：

- 以上配置信息仅用于本次活动，活动结束后将会收回。
- 课题内部共用同一个 EP 和 API Key，需要合理使用资源，避免浪费。
- API Key 不要写入 README、源码、截图、提交记录或公开文档。
- 如需在工程中使用，建议通过 `.env`、本机环境变量或 IDE 私密配置保存。

### 7.2 配置步骤

1. 打开 TRAE IDE。
2. 在界面左下角点击“设置”图标，即齿轮按钮。
3. 也可以使用快捷键打开设置：
   - Windows / Linux：`Ctrl + ,`
   - macOS：`Cmd + ,`
4. 在设置页面左侧导航栏中，点击“模型”或 `Model` 选项卡。
5. 在模型配置界面中，点击“自定义模型”或“添加模型”。
6. 按赛事方要求填写配置：

| 字段     | 填写方式                         |
| -------- | -------------------------------- |
| Endpoint | 选择“火山引擎 - 自定义模型”    |
| Model ID | 填入比赛提供的 EP                |
| API Key  | 填入导师或比赛平台提供的 API Key |

填写完成后，点击“保存”或“应用”按钮，使配置生效。

> 截图备注：如后续补充 TRAE 配置页面截图，必须遮挡 API Key。

### 7.3 测试与确认

配置完成后，可以按以下方式验证：

1. 打开 TRAE IDE 的 AI 聊天窗口，即 `Chat`。
2. 在模型下拉菜单中选择刚刚配置的自定义模型。
3. 输入一个简单问题，例如：

```text
你好，请介绍一下你自己。
```

如果模型能够正常回复，说明配置已成功。

### 7.4 常见问题排查

如果配置过程中遇到报错，优先检查：

- Endpoint 或服务商是否选择正确。
- Model ID 是否填写为比赛提供的 EP。
- API Key 是否复制完整，是否包含多余空格。
- API Key 是否还有余量或是否已过期。
- 当前网络环境是否能访问对应服务。
- 是否已经点击“保存”或“应用”。

如仍无法解决，记录报错信息、配置项截图和复现步骤后，提交到团队问题记录或比赛答疑文档。

## 8. 评审维度与加分项

### 8.1 功能完整性

主链路必须可用：

1. 拍照识物
2. 导购建议卡片
3. 自然语言追加筛选
4. 推荐列表刷新

体验要求：

- 端到端体验流畅。
- 演示路径清晰。
- 评委能快速验证核心功能。

可选加分项：

- 历史价格走势
- 评价风险判断
- 个性化推荐
- 同款 / 相似款解释
- 商品对比表
- 购买决策理由与证据链

### 8.2 工程架构

重点关注：

- 前后端交互设计是否合理。
- 数据源模块是否易于扩展。
- 是否能便捷接入新的电商平台。
- AI 模块是否可插拔。
- 模型替换与升级成本是否较低。
- API 文档、数据结构、错误处理是否规范。

### 8.3 AI 工具使用

重点关注：

- 是否超越简单 API 单次调用。
- 是否体现复杂 AI 任务编排能力。
- Prompt 设计是否鲁棒。
- 是否能稳定输出结构化数据。
- 是否有结构化校验、重试、降级或兜底逻辑。

可选加分项：

- AI Coding 心得沉淀。
- Cursor、TRAE 等工具的上下文管理方法。
- 约束边界设定经验。
- 代码幻觉识别与纠偏过程。
