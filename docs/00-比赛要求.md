# 赛事官方要求：AI 拍照识物与智能比价购物助手

本文档记录赛事官方课题要求，作为项目需求、验收与答辩口径的最高优先级基线。本文只保留官方要求本身，不混入当前项目实现状态；当前实现进度见 [01-项目范围与进度.md](01-项目范围与进度.md)，实现边界见 [18-当前实现边界与问题清单.md](18-当前实现边界与问题清单.md)。

## 背景

在日常生活中，用户常遇到“看到想买但难以检索”的问题：面对街头同款服饰、短视频里的数码产品，往往缺少品牌/款式等关键信息；即使使用截图或以图搜图，也容易出现匹配不准、结果过多、跨平台比价成本高等情况，影响决策效率。

本课题旨在通过 AI 技术打通“识别—检索—决策”链路，构建一款「AI 拍照识物与智能比价购物助手」。用户完成一次拍摄后，系统可识别商品并聚合多平台推荐结果，同时支持自然语言追加筛选（如“500 元以内”），辅助用户快速收敛候选并完成决策。

项目重点在于：如何应用 VLM 视觉模型进行非结构化信息解析；如何通过 LLM 编排与 Prompt 工程实现意图理解与结构化输出等。我们希望大家通过技术创新，缩短用户从“产生购买意愿”到“完成消费决策”的转化路径，打造极致流畅的智能化购物体验。

## 项目要求

实现一款面向 C 端消费者的 AI 拍照识物购物助手。客户端通过摄像头采集商品图像并上传服务端；服务端完成商品类目与关键属性（款式、颜色、品牌等）识别后，动态生成下一步决策建议卡片（如“查看同款低价”“只看旗舰店”“相似爆款推荐”等）。用户点击建议卡片后，系统跨平台匹配相似商品并输出推荐列表；同时支持用户通过自然语言追加筛选条件，购物助手实时刷新推荐结果，辅助用户高效完成购买决策。

## 功能要求

### 拍照识物

- 支持通过 App 内的相机拍摄商品。
- 输出识别结果，包含主要类目与关键属性（品牌、颜色等）。
- 基于识别关键词跨平台召回相似商品，生成推荐列表。
- 支持用户对识别错误的关键属性进行修正（例如，将“蓝色”修正为“深蓝色”）。

### 智能建议卡片

- 在识别结果下方，动态生成一组可交互的建议卡片，引导用户进入下一步购买决策。
- 卡片示例：“查看同款低价”“只看官方旗舰店”“相似风格推荐”“查看历史价格走势”“筛选：颜色/品牌/尺码”。

### 跨平台比价

- 聚合多平台同款商品，展示各平台的最低价和平台均价。

### 自然语言追加筛选

- 支持用户在输入框中通过自然语言追加筛选条件。
- 示例：识别出“运动鞋”后，用户可输入“帮我找 1000 元以内的黑色款，要评价 4.8 分以上的”。

### 推荐列表与排序

- 以卡片形式展示商品列表，每张卡片包含商品图、名称、价格、来源平台与关键标签（如“自营”“官方”）。
- 提供多种排序方式：综合推荐、价格从低到高、销量优先、好评率等。

## 技术架构

### 推荐技术栈

客户端（Android / iOS）：

- 核心任务：摄像头图片采集、图片上传、交互界面（建议卡片、筛选器）的实现、商品列表渲染。
- 技术要点：掌握原生或跨平台框架（如 Flutter/React Native）的摄像头 API、网络请求、UI 布局与状态管理。

服务端（Go / Java / Python / Node.js）：

- 核心任务：提供 API 接口（REST/GraphQL）、编排 AI 识别与检索任务、聚合多平台数据、管理数据存储与缓存。
- 技术要点：掌握至少一门后端语言及主流框架，遵循设计原则，编写规范 API 接口。

## 技术与合规边界

### 允许

- AI 能力：不限 AI 模型，不限 AI Coding 工具。可自由组合各类大模型 API 进行开发（推荐：火山引擎 OpenAPI + TRAE IDE）。
- 合法数据源：使用公开合法的电商平台 API 或公开样例数据集进行比价。在缺乏合规 API 或数据来源的情况下，允许进行数据模拟，但严禁任何形式的非法数据采集。
- 技术栈自由：在推荐的技术栈基础上，可以根据团队熟悉度自由选择具体实现。

### 限制

- 禁用端侧 AI SDK：为聚焦服务端架构与 AI Pipeline 的能力建设，严禁使用任何形式的端侧 AI 识别 SDK（如豆包 SDK、Google ML Kit、百度 AI SDK、阿里云视觉智能 SDK 等），所有 AI 计算须在云端完成。
- 禁止非法数据采集：不得编写任何形式的网络爬虫，或以违反平台服务条款的方式获取数据。

- EP：赛事提供的专用 Endpoint，占位记录，不在仓库写入真实值
- APIKEY：赛事提供的专用 API Key，占位记录，不在仓库写入真实值

使用规则：

1. EP / API Key 仅限本课题挑战开发使用，严禁外泄、严禁用于非挑战项目。
2. 项目组实时观测调用流量，发现异常将直接封禁应用 / IP。
3. 受资源限制建议错峰调用（建议避开北京时间 14:00-18:00 高峰）。

## 评审维度与加分项

### 功能完整性

- 主链路可用：拍照识物、导购建议、自然语言过滤三大核心功能完整落地，端到端体验流畅。
- 功能拓展（可选，加分项）：基于核心课题思路，有合理的业务场景或体验延伸。

### 工程架构

- 可扩展性：前后端交互设计合理；数据源模块易于扩展，可便捷接入新的电商平台；AI 模块支持可插拔，便于后续模型的低成本替换与升级等。

### AI 工具使用

- 工程中 AI 任务编排与 Prompt 设计：超越简单的 API 单次调用，体现对复杂 AI 任务的合理编排；系统 Prompt 设计具备良好的鲁棒性，能稳定输出结构化数据等。
- AI Coding 心得沉淀（可选，加分项）：高效使用 AI 辅助编码，沉淀 AI Coding 工具（如 Cursor、Trae 等）的使用思路与流程。例如：如何做上下文管理、如何设定约束边界、遇到代码幻觉时如何调优纠偏。
