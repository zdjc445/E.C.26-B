# 核心流程设计

## 主链路流程

```text
用户进入聊天首页
    → 在底部输入框输入文字 / 添加图片
    → APP 上传图片并发送聊天消息
    → Mock Agent 判断信息是否足够
    → 信息不足：返回追问卡片
    → 用户点击追问选项
    → 信息足够：返回推荐卡片
```

## 详细流程说明

### 1. 进入聊天首页

1. APP 启动后进入 `/home`
2. 页面主体为聊天消息列表
3. 页面底部固定输入栏，包含图片按钮、文字输入框、语音占位按钮和发送按钮
4. 登录入口当前保留为占位能力，不影响聊天首页使用

### 2. 用户发送文字或图片

1. 用户可以直接输入自然语言购物需求
2. 用户可以通过图片按钮选择商品图片
3. 图片选择后，APP 调用 `POST /api/images/upload`
4. 上传成功后，APP 将 `imageId` 与文本一起发送到聊天接口
5. 如果还没有 `sessionId`，APP 先调用 `POST /api/chat/sessions`

### 3. Mock Agent 追问

1. APP 调用 `POST /api/chat/sessions/{sessionId}/messages`
2. Mock Agent 接收 `text`、`imageIds`、`selectedOptionIds`
3. 当用户偏好不明确时，Agent 返回追问卡片
4. 追问卡片固定包含：
   - 价格最低
   - 官方店铺
   - 配送更快
5. 用户点击卡片选项即可继续，不需要必须输入文字

### 4. 推荐卡片

1. 用户点击追问选项后，APP 再次调用聊天消息接口
2. Mock Agent 根据选项返回推荐卡片
3. 推荐卡片展示：
   - 商品名
   - 平台
   - 价格
   - 推荐理由
4. 当前直接把 Mock 数据视为不同平台来源展示，推荐卡片的平台名称统一带 `-mock` 后缀
5. 当前推荐内容来自人工构造的 Mock 数据，不代表真实平台结果

### 5. 语音描述

1. 输入栏提供语音按钮
2. 当前阶段不进行真实录音和语音识别
3. 点击后只显示占位提示
4. 后续接入真实语音识别后，再将识别文本送入聊天消息接口

## 当前阶段状态

当前阶段目标是实现聊天式 Mock Agent 闭环。真实 AI 识别、真实商品搜索、跨平台比价、认证、持久化、收藏和价格提醒均为后续迭代。
