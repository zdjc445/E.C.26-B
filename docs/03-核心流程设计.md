# 核心流程设计

## 主链路流程

```text
用户进入聊天首页
  → 输入文字需求 / 添加商品图片
  → 文本购物意图识别或图片 AI/Mock 识别
  → 信息不足时返回追问卡片
  → 用户点击偏好选项
  → Agent 结合上下文生成多平台 Mock 商品
  → 返回商品列表卡、比价卡和推荐卡
  → 历史会话恢复完整 agentReply 卡片
```

## 文字需求流程

1. 用户在底部输入框输入购物需求，例如 `我想买300以内的耳机，价格低一点`。
2. APP 创建或复用 `sessionId`，调用聊天消息接口。
3. Agent 用规则识别购物意图和预算：
   - 支持 `300以内`、`300以下`、`不超过300`、`预算300` 等预算表达。
   - 支持当前 Mock 品类：运动鞋、耳机、吹风机。
4. 后端通过 `MockProductSourceProvider` 生成三平台商品。
5. `RecommendationScorer` 根据偏好和商品特征排序。
6. 返回：
   - `product_list`：多平台商品结果
   - `comparison`：平台最低价与商品数量
   - `recommendation`：推荐购买

## 图片识别流程

1. 用户通过图片按钮拍照或从相册选择图片。
2. APP 调用 `POST /api/images/upload` 上传图片。
3. APP 将 `imageId` 发送到聊天消息接口。
4. 后端校验图片元数据和本地文件。
5. 后端调用 AI Provider：
   - `AI_PROVIDER=mock`：使用 Mock 识别。
   - `AI_PROVIDER=ark`：调用 Ark；失败时回退 Mock。
6. 返回 `recognition` 卡片和 `clarification` 追问卡片。
7. 用户点击追问选项后，Agent 从历史 `recognition` 卡片继承 category，用于商品推荐。

## 识别修正流程

1. 用户在识别卡片点击修正入口。
2. APP 打开修正面板，用户可修改类别、品牌、型号和属性。
3. APP 调用 `PATCH /api/recognition/{recognitionId}/attributes`。
4. 后端更新内存识别结果。
5. APP 更新当前聊天卡片。

## 追问与推荐流程

追问卡片固定包含：

| optionId | label |
|----------|-------|
| lowest_price | 价格最低 |
| official_store | 官方店铺 |
| fast_delivery | 配送更快 |

点击选项后：

- 后端读取最近用户文本，用于继承预算。
- 后端读取最近识别卡片，用于继承识别 category。
- 后端生成商品列表、比价和推荐。

## 超预算流程

当预算过滤后没有商品时，后端仍返回稳定卡片结构：

- `product_list`：`products` 为空
- `comparison`：`platformStats` 为空

Flutter 端展示：

- `暂无符合条件的商品`
- `暂无可比价平台`

## 历史恢复流程

1. 用户打开左上角历史入口。
2. APP 调用会话列表接口。
3. 用户切换会话后，APP 调用历史消息接口。
4. 后端在 assistant 消息中返回完整 `agentReply`。
5. Flutter 根据 `agentReply.cards` 恢复识别卡、追问卡、商品列表卡、比价卡和推荐卡。

## 语音描述

语音按钮当前为占位能力。点击后只展示提示，不进行真实录音或语音识别。真实语音识别为后续迭代。
