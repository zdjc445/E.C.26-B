# 核心流程设计

## 主链路流程

```text
用户进入聊天首页
  → 输入文字需求 / 添加商品图片
  → 文本购物意图识别或图片 AI/Mock 识别
  → 信息不足时返回动态建议卡（按识别 category 生成 6 个差异化选项）
  → 用户点击建议选项 / 继续输入追加筛选条件
  → Agent 结合上下文生成多平台 Mock 商品
  → 生成推荐解释：综合分、决策信号、证据摘要、风险提示
  → 返回商品列表卡、比价卡和推荐卡
  → 历史会话恢复完整 agentReply 卡片
```

## 文字需求流程

1. 用户在底部输入框输入购物需求，例如 `我想买300以内的耳机，价格低一点`。
2. APP 创建或复用 `sessionId`，调用聊天消息接口。
3. Agent 解析购物意图和偏好：
   - 默认使用规则解析。
   - `AI_PROVIDER=ark` 时优先使用 Ark 意图解析；Ark 不可用时回退规则解析。
   - 支持 11 维字段：品类 / 预算 / 颜色 / 品牌 / 平台 / 排序方式 / 最低评分 / 官方旗舰自营 / 配送 / 低价 / 好评 / 销量倾向。
   - 支持当前 Mock 品类：运动鞋、耳机、吹风机、背包、智能手表。
   - 支持在同一会话中继续输入 `只看300以内的黑色款`、`只看京东的`、`4.8分以上`、`价格从低到高` 等追加筛选条件。
4. 后端通过 `MockProductSourceProvider` 生成三平台商品，按预算 → 颜色 → 品牌 → 平台 → 最低评分顺序过滤，按 sortBy 排序。
5. `RecommendationScorer` 根据偏好和商品特征评分，并记录命中偏好 key。
6. `RecommendationExplainer` 生成综合分、决策信号、证据摘要、风险提示和商品胜因/不足；`AI_PROVIDER=ark` 时可由 Ark 改写解释文本，失败时回退规则解释。
7. 返回：
   - `product_list`：多平台商品结果（含品牌、价格走势、命中偏好）
   - `comparison`：平台最低价、均价、商品数量、亮点
   - `recommendation`：推荐购买、解释字段和 Provider 状态

## 图片识别流程

1. 用户通过图片按钮拍照或从相册选择图片。
2. APP 调用 `POST /api/images/upload` 上传图片。
3. APP 将 `imageId` 发送到聊天消息接口。
4. 后端校验图片元数据和本地文件。
5. 后端调用 AI Provider：
   - `AI_PROVIDER=mock`：使用 Mock 识别。
   - `AI_PROVIDER=ark`：调用 Ark；失败时回退 Mock。
6. 返回 `recognition` 卡片和 `clarification` 动态建议卡。
7. 用户点击建议选项或继续输入追加筛选条件后，Agent 可从历史 `recognition` 卡片继承 category，用于商品推荐。

## 多轮自然语言追加筛选流程

用户在一次推荐后继续输入短句时，后端会把当前文本和会话历史合并为本轮检索条件。

示例：

```text
推荐耳机
  → 只看300以内的黑色款
  → 商品仍为耳机，并按 ≤300 元和黑色过滤
  → 只看京东的
  → 商品仍为耳机，价格 ≤300，黑色，仅京东-mock
  → 4.8分以上
  → 商品仍为耳机，价格 ≤300，黑色，仅京东-mock，rating ≥4.8
```

当前上下文合并规则（`MockAgent.mergeContext`）：

- 品类优先级：当前文本明确品类 > 历史文本明确品类 > 历史识别卡 category > 默认运动鞋。
- 数值字段（`maxPrice`、`color`、`brand`、`platforms`、`sortBy`、`minRating`）使用最近一次明确值；当前文本有明确值时覆盖历史值。
- 偏好布尔（`officialStore`、`fastDelivery`、`lowestPrice`、`highRating`、`highSales`）在同一会话中累积。
- 商品检索时通过 `ProductSearchQuery` 传入 `keyword`、`preferences`、`maxPrice`、`color`、`brand`、`platforms`、`sortBy`、`minRating`。
- 颜色过滤匹配商品 `title` 或 `tags` 中包含的颜色文本。
- 品牌过滤匹配商品 `brand` 字段或 `title` 中含品牌字。
- 平台过滤精确匹配 `京东-mock / 拼多多-mock / 淘宝-mock`。

## 识别修正流程

1. 用户在识别卡片点击修正入口。
2. APP 打开修正面板，用户可修改类别、品牌、型号和属性。
3. APP 调用 `PATCH /api/recognition/{recognitionId}/attributes`。
4. 后端更新内存识别结果。
5. APP 更新当前聊天卡片。

## 动态建议卡流程

`MockAgent.buildSuggestionCard(category, brand)` 根据识别 category 与品牌生成差异化建议：

| category | 额外选项 |
|----------|----------|
| 运动鞋 | `相似风格推荐`、`筛选颜色/品牌/尺码` |
| 耳机 | `降噪款优先`、`好评率优先` |
| 吹风机 | `大功率优先`、`便携折叠款` |
| 背包 | `大容量款`、`商务款` |
| 智能手表 | `长续航款`、`运动款` |

每张建议卡固定包含：

| optionId | label |
|----------|-------|
| lowest_price | 查看同款低价 |
| official_store | 只看官方旗舰店 |
| fast_delivery | 配送更快 |
| price_history | 查看历史价格走势 |

识别到品牌时额外添加 `filter_same_brand` → `只看 {品牌}`。

点击选项后：

- 后端读取最近用户文本和会话历史，用于继承文本偏好、品牌、平台、排序、最低评分。
- 后端读取最近识别卡片，用于继承识别 category。
- 后端生成商品列表、比价、推荐和结构化解释。
- 点击 `lowest_price` 时若 sortBy 未设，则自动按 price_asc 排序。

## 超预算 / 筛选过严流程

当过滤后没有商品时，后端仍返回稳定卡片结构：

- `product_list`：`products` 为空
- `comparison`：`platformStats` 为空

Flutter 端展示：

- `暂无符合条件的商品`
- `暂无可比价平台`

回复文本会按当前筛选维度提示用户：「当前筛选（预算 ≤ 50 元、品牌 索尼、颜色 黑色）下暂无合适的 Mock 商品，请放宽条件。」

## 历史恢复流程

1. 用户打开左上角历史入口。
2. APP 调用会话列表接口。
3. 用户切换会话后，APP 调用历史消息接口。
4. 后端在 assistant 消息中返回完整 `agentReply`。
5. Flutter 根据 `agentReply.cards` 恢复识别卡、动态建议卡、商品列表卡、比价卡、推荐卡和推荐解释字段，包括品牌徽章、价格走势、命中偏好徽章、Provider 状态徽章。

## 语音描述

语音按钮当前为占位能力。点击后只展示提示，不进行真实录音或语音识别。真实语音识别为后续迭代。
