# 测试方案

## 测试目标

验证系统是否能稳定完成 API 契约定义的购物决策闭环：

```text
上传图片
  -> 创建识别任务
  -> 创建搜索任务
  -> 创建比价
  -> 查询历史价格和评价摘要
  -> 创建 Agent 推荐
```

主链路 ID：

```text
imageId -> recognitionId -> searchTaskId -> comparisonId -> recommendationId
```

## 接口契约测试

| 测试项 | 验收标准 |
| --- | --- |
| 统一响应 | 所有接口响应都包含 `code`、`message`、`data` |
| 分页结构 | 列表接口返回 `items`、`page`、`pageSize`、`total` |
| 字段命名 | API JSON 字段使用小驼峰 |
| ID 类型 | API 示例中的 ID 使用数字类型 |
| 金额结构 | 金额统一为 `amount` 和 `currency` |
| 用户归属 | 用户私有接口请求体不允许出现 `userId` |
| 错误码 | 权限、资源不存在、参数错误都有明确错误码 |

## 功能测试

| 功能 | 测试点 |
| --- | --- |
| 用户注册登录 | 能注册、登录、刷新 Token、退出登录、获取当前用户信息 |
| 图片上传 | 支持常见图片格式，失败时有错误提示 |
| 商品识别 | 能返回 `recognitionId`、类别、关键词和置信度 |
| 搜索任务 | 能根据 `recognitionId` 或 `query` 创建 `searchTaskId` |
| 搜索结果 | 候选商品包含平台、价格、来源、`matchScore` |
| 比价 | 能基于 `searchTaskId` 和候选商品生成 `comparisonId` |
| 历史价格 | 能展示当前价、最高价、最低价和趋势 |
| 评价摘要 | 能返回正向标签、风险标签和风险分 |
| Agent 推荐 | 能生成 `recommendationId`、推荐商品、理由、风险和 `evidence` |
| 收藏与提醒 | 当前用户只能看到自己的收藏和价格提醒 |

## 完整链路测试

测试流程：

```text
POST /api/images
  -> POST /api/recognitions
  -> POST /api/search-tasks
  -> POST /api/comparisons
  -> GET /api/platform-products/{platformProductId}/price-history
  -> GET /api/platform-products/{platformProductId}/review-summary
  -> POST /api/agent/recommendations
```

验收标准：

- 每一步返回的 ID 能被下一步使用
- `candidateIds` 必须来自当前 `searchTaskId`
- Agent 推荐结果必须包含 `evidence`
- 搜索结果为空、识别低置信度、历史价格为空都有明确响应

## 数据隔离测试

准备两个测试用户：

- user_a
- user_b

测试场景：

- user_a 创建的 `imageId`，user_b 不能查询或删除
- user_a 创建的 `recognitionId`，user_b 不能读取
- user_a 创建的 `searchTaskId`，user_b 不能读取或用于推荐
- user_a 创建的 `recommendationId`，user_b 不能查询
- user_a 创建的 `favoriteId` 和 `priceAlertId`，user_b 不能查询、修改或删除
- 跨用户访问私有资源时返回 404 或 403，不返回其他用户数据

## 登录验收测试

- 注册成功后，`users.password_hash` 不等于原始密码
- 重复注册同一个 username，应返回用户名已存在
- 使用错误密码登录，应返回登录失败
- 禁用用户登录，应返回账号不可用
- 登录成功后，响应中包含 accessToken、refreshToken、expiresIn 和 user
- 访问私有接口不带 accessToken，应返回 401
- 使用 refreshToken 可以换取新的 accessToken
- 退出登录后，原 refreshToken 不能再次刷新

## AI 效果评估

准备测试样例：

- 手机
- 耳机
- 吹风机
- 键盘
- 水杯
- 运动鞋
- 护肤品

评估指标：

- 识别是否正确
- 候选商品是否相关
- `matchScore` 是否合理
- 推荐理由是否能追溯到 `evidence`
- 风险提示是否来自评价摘要或历史价格
