# 用户认证与数据隔离

## 设计目标

系统需要支持多用户使用，不同用户之间的私有数据必须隔离。

需要隔离的数据包括：

- 上传图片
- 商品识别记录
- 搜索历史
- 搜索任务结果
- 比价记录
- Agent 推荐记录和证据链
- 收藏商品
- 价格提醒
- 用户偏好

公共商品数据可以复用：

- 标准商品信息
- 平台商品信息
- 公共价格记录

## 落地方案

MVP 阶段采用“用户名 + 密码 + access token + refresh token”的方案。

| 项目 | 设计 |
| --- | --- |
| 登录凭证 | 用户名和密码 |
| 密码存储 | BCrypt 或 Argon2id 哈希 |
| access token | JWT，建议 2 小时过期 |
| refresh token | 随机字符串，建议 14 天过期 |
| refresh token 存储 | 服务端只存哈希 |
| 退出登录 | 将 refresh token 对应会话标记为失效 |
| 当前用户来源 | 后端从 access token 解析 |

## 登录流程

```text
用户注册
  -> 后端校验用户名和密码格式
  -> 密码哈希入库
  -> 用户登录
  -> 后端签发 access token 和 refresh token
  -> 后端保存 refresh token 哈希
  -> 前端保存 token
  -> 后续请求携带 Authorization Header
  -> 后端解析当前用户
  -> 执行业务逻辑
```

## 鉴权方案

业务接口使用 access token：

```http
Authorization: Bearer <accessToken>
```

access token 中只保存必要信息：

```json
{
  "userId": 1,
  "username": "alice",
  "status": "active"
}
```

refresh token 不放在 JWT 里，使用随机字符串生成，并在服务端保存哈希值。

## 后端权限原则

- 除注册、登录、刷新 Token、退出登录外，默认接口都需要登录
- 当前用户只能由后端从 Token 或 Session 中解析
- 请求体中的 user_id 不能作为权限依据
- 查询用户私有数据时必须自动追加 user_id 条件
- 修改或删除数据前必须校验数据所有权
- 禁用用户不能登录，已登录用户在下一次 Token 刷新或敏感操作时需要重新校验状态

## 密码规则

MVP 阶段建议先使用简单但明确的规则：

- 用户名长度 3 到 32 位
- 用户名只允许字母、数字、下划线
- 密码长度至少 8 位
- 密码不能和用户名完全相同
- 密码不允许明文落库或写入日志

## 后端实现步骤

1. 建立 `users` 和 `user_sessions` 表
2. 实现注册接口，完成参数校验、用户名唯一校验、密码哈希入库
3. 实现登录接口，校验用户状态和密码哈希
4. 登录成功后签发 access token，并保存 refresh token 哈希
5. 实现鉴权中间件，从 `Authorization` 请求头解析当前用户
6. 实现刷新 Token 接口，校验 refresh token 是否存在、未过期、未撤销
7. 实现退出登录接口，将会话标记为撤销
8. 所有私有数据接口从鉴权上下文获取 currentUserId

| 数据 | 是否用户私有 | 归属字段 |

| users | 是 | id |
| user_sessions | 是 | user_id |
| products | 否 | 无 |
| platform_products | 否 | 无 |
| price_records | 否 | 无 |
| uploaded_images | 是 | user_id |
| recognitions | 是 | user_id |

## 查询示例

错误做法：

```sql
SELECT * FROM favorites WHERE id = :favoriteId;
```

正确做法：

```sql
SELECT * FROM favorites
WHERE id = :favoriteId
  AND user_id = :currentUserId;
```

## Agent 数据隔离

Agent 只能读取当前用户授权范围内的数据：

- 当前用户的图片和识别记录
- 当前用户的搜索任务和候选结果
- 当前用户的比价记录
- 当前用户的推荐记录和 evidence
- 当前用户的收藏
- 当前用户的价格提醒

Agent 可以读取公共商品库和公共价格记录，但不能跨用户读取其他人的私有行为数据。

## 异常处理

| 场景 | 处理方式 |
| --- | --- |
| 未登录访问私有接口 | 返回 401 |
| Token 无效或过期 | 返回 401 |
| refresh token 无效或过期 | 返回 401 |
| 访问其他用户数据 | 返回 403 或 404 |
| 删除不存在的数据 | 返回 404 |

## 开发验收标准

- 注册后数据库中只出现 `password_hash`，不能出现明文密码
- 重复用户名注册必须失败
- 错误密码登录必须失败
- 禁用用户登录必须失败
- 不带 access token 访问私有接口必须返回 401
- 过期 access token 必须返回 401
- refresh token 能换取新的 access token
- 退出登录后，同一个 refresh token 不能再次刷新
