# 前端设计重构说明

## 设计参考

本轮前端重构不再追求“看起来很 AI”，而是转向成熟工具型产品的工作台质感。

参考方向：

- Linear 的最新 UI refresh：降低导航和装饰权重，让主工作区优先；用更一致的 header、视图控制和更柔和的分隔线支撑高密度信息。参考：https://linear.app/now/behind-the-latest-design-refresh
- Apple Human Interface Guidelines：强调清晰层级、可理解的控制和跨屏幕一致性。参考：https://developer.apple.com/design/human-interface-guidelines
- Material Design layout：用稳定的 app bar、navigation、body 区域和一致间距建立可预测布局。参考：https://m2.material.io/design/layout/understanding-layout.html
- Shopify Polaris/Admin 类产品经验：后台工具应优先保证一致组件、信息架构、可扫描表格和低学习成本。参考：https://shopify.dev/docs/api/polaris/using-polaris-web-components

## 反套路 Prompt

后续如果继续用 AI 辅助前端设计，使用下面的约束，避免回到模板化 UI：

```text
设计一个真实产品的操作界面，而不是营销落地页。
目标用户会反复使用它完成购物决策，所以界面应低噪声、高密度、可扫描。
禁止紫蓝渐变背景、玻璃拟态、漂浮装饰球、过度圆角、三张功能卡片式布局、巨大的 hero 标语和“AI 感”徽标。
先建立信息层级：主决策、候选、证据、筛选、资产沉淀。
颜色先用灰阶和边框建立结构，再用少量蓝/绿/红/琥珀表达状态。
按钮、输入、筛选、列表、矩阵都应像一个成熟工作台，而不是演示模板。
每个可视模块必须回答一个实际问题：当前推荐是什么、为什么不是最低价、风险在哪里、下一步能做什么。
```

## 已落地调整

- Web/PWA：品牌从 `AI` 改为 `E.C.26-B`，整体命名改为“购物决策工作台”。
- Web/PWA：改成中性工作台配色，降低绿色占比，减少模板化视觉。
- Web/PWA：保留左侧操作区和右侧工作区，但强化 sticky 顶部控制、摘要栏、Agent 证据区和候选矩阵的层级。
- Web/PWA：Agent 面板新增“价格-可信度取舍”，直接解释推荐项与最低价之间的差额和渠道确定性。
- Web/PWA：PWA manifest、SVG/PNG 图标同步替换为工作台风格。
- Flutter：核心 ThemeData 与 Web 统一为中性工作台风格。
- Flutter：首页去掉渐变 hero 和“AI 助手”话术，改成工作台 header、密集入口和状态条。
- Flutter：推荐页新增决策分、五类信号、六步轨迹和候选矩阵展示。
- Flutter：登录页、识别页和商品洞察页移除显眼 AI 话术，改为识别源/评价摘要等更产品化表达。
- Flutter 识别结果页：从“接口返回数据面板”重构为消费级识别结果页，页面顺序调整为“识别主视觉 -> 下一步建议 -> 识别判断 -> 识别细节 -> 折叠纠错”。顶部集中展示商品名、置信度、识别源、fallback 状态、核心属性和关键词；建议卡改为行动列表；属性编辑弱化为“纠正识别结果”折叠面板。
- 2026-06-01 继续优化：Web/PWA 工作区增加低噪声信号纹理、品牌标识扫光、结果区进场、决策条流光和信号条填充动效；识别按钮增加 busy 文案；Flutter 识别加载视觉增加移动扫描线，强化双端“正在解析”的动态反馈。

## 参考依据

- [Baymard Product Page UX Best Practices 2026](https://baymard.com/blog/current-state-ecommerce-product-page-ux)：商品页应优先帮助用户完成购买判断，而不是罗列字段。
- [Baymard Mobile UX: Avoid Subpages on Product Pages](https://baymard.com/blog/avoid-using-subpages)：移动端复杂商品信息适合用主页面内的分区和折叠组织，避免让用户丢失上下文。
- [NN/g 5 Visual-design Principles in UX](https://media.nngroup.com/media/articles/attachments/Principles_Visual_Design-Letter.pdf)：用尺度、层级、对比和格式塔关系控制注意力顺序。
- [Shuffle: Why Do Most AI-Generated Websites Look the Same?](https://shuffle.dev/blog/2026/01/why-do-most-ai-generated-websites-look-the-same/)：避免泛化 AI 风格的关键是明确区块顺序、布局逻辑、视觉边界和功能目标。

## Flutter 识别页结构

识别结果页现在按用户决策路径组织，而不是按接口字段顺序排列：

| 层级 | 目的 | 设计处理 |
| --- | --- | --- |
| 识别主视觉 | 让用户立刻确认“系统识别出来了什么” | 扫描感占位视觉、商品名、置信度、识别源、核心属性集中展示 |
| 下一步建议 | 把识别结果转化为可行动入口 | 统一行动列表样式，使用 `AppColors` 的 good/warn/priceRed/signal 表达状态 |
| 识别判断 | 解释识别依据和仍需确认的信息 | 合并 explanation 与 notices，避免拆成多张白卡 |
| 识别细节 | 给需要核对的用户看完整属性 | 细线列表和浅背景组织，保持可扫读 |
| 纠正识别结果 | 保留编辑能力但降低视觉重量 | 折叠面板，只有识别不准时展开修改并保存 |

## 后续审美标准

- 页面第一眼必须像可投入使用的购物决策工具，而不是生成式模板。
- 功能入口优先靠位置、分组和状态表达，不靠长说明文字。
- 视觉资产、图标和按钮保持克制，主舞台留给商品、价格、风险和证据。
- 新增模块必须复用现有 token、间距、边框、状态色，避免单点样式漂移。
