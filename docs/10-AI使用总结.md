# AI 使用总结

本文档总结本项目在工程中如何编排 AI 任务、设计 Prompt、保障鲁棒性，以及团队在 AI 辅助编码（AI Coding）中的实践沉淀。重点贴合赛题评审维度的「AI 任务编排与 Prompt 设计」与「AI Coding 心得沉淀」两条主线。

## 1. 工程中的 AI 编排

### 三条 AI 链路

| 链路 | 入参 | 出参 | Provider |
|------|------|------|----------|
| 图片识别 | imageId + bytes + contentType | `category / brand / model / keywords / attributes / confidence / explanation` | `MockRecognitionProvider` / `ArkRecognitionProvider`，外层 `FallbackRecognitionProvider` 控制回退 |
| 购物意图解析 | 用户文本 | `keyword / maxPrice / color / brand / platforms / sortBy / minRating / preferences / needsClarification` | `RuleBasedShoppingIntentParser` / `ArkShoppingIntentParser`，外层 `FallbackShoppingIntentParser` |
| 查询拆解与检索增强 | 用户文本 + 商品目录 | 标准品类、扩展词、混合检索分数、重排结果 | `ArkQueryDecomposer` / `QueryRewriter` / `HybridRetriever` / `ResultReRanker` |
| 推荐解释改写 | 规则生成的 `RecommendationExplanation` + ShoppingIntent + 商品集合 | 改写后的 `summaryReason / signals / evidence / risks / analyses` | `RecommendationExplainer`（规则）/ `ArkRecommendationExplainer`（Ark 改写） |

### 编排策略

- **Mock 优先打通闭环：** 任何时候 Mock Provider 都能独立返回稳定结构，保证演示不中断。
- **Ark 增强而非替代：** Ark 不允许修改 `productId`、`platform`、`price`、`productName`、`score`、`decisionScore` 等结构化字段，只能改写面向用户的文本解释。
- **失败回退记账：** 任何 Ark 失败都会通过 `intentFallbackUsed` / `explanationFallbackUsed` 和 `notices` 字段透传到 UI 徽章，便于评委验证回退路径。
- **多轮上下文合并：** Agent 在 `MockAgent.mergeContext` 中跨轮合并：当前文本明确值 > 历史文本最新值 > 历史识别元数据 category > 默认值；预算/颜色/品牌/平台/排序/最低评分按「最新明确值覆盖」，偏好布尔位按「累积」。
- **图像归一化：** `ArkRecognitionProvider.normalizeContentType` 通过 JPEG/PNG 头检测覆盖错误声明的 `application/octet-stream`，并默认到 `image/jpeg`，提升 Ark 接受成功率。

## 2. Prompt 设计要点

### 意图解析 Prompt（`ArkShoppingIntentParser`）

> 你是电商购物意图解析器。只输出 JSON。字段固定为：keyword、maxPrice、color、officialStore、fastDelivery、lowestPrice、highRating、highSales、brand、platforms、sortBy、minRating、needsClarification、clarificationQuestion。平台值进入代码白名单校验，当前白名单为 `京东-mock`、`拼多多-mock`、`淘宝-mock`、`天猫-mock`。

设计要点：
- **枚举字段封顶：** 平台、排序、品类全部用枚举约束，越界时由代码兜底到默认值。
- **数值字段加范围：** `minRating` 限制 0-5，`maxPrice` 为正数，否则丢弃。
- **不允许 Markdown：** 强制纯 JSON 输出，`ArkClient.extractJsonObject` 仍然做了一层 ```json``` 与 `{}` 包裹剥离，防止 markdown 残留。
- **保留 needsClarification：** 让 Ark 自行判断信息不足，并回退到规则解析。

### 推荐解释 Prompt（`ArkRecommendationExplainer`）

> 你是电商推荐顾问。只输出 JSON，字段固定为 summaryReason(string), signals(array of {key,label,explanation}), evidence(array of {type,content}), risks(array of string), analyses(array of {productId,strengths(array),weaknesses(array)})。不要修改 productId、platform、price、productName、score、decisionScore。不要输出 Markdown。

设计要点：
- **白名单字段：** Ark 只能改写文本，结构化字段全部由代码强制保留原值。`rewriteAnalyses` 始终用规则生成的 `productId / platform / title / rank / score`。
- **上下文打包：** 把规则解释、意图、商品摘要按 JSON 喂给 Ark，避免 Ark 自由发挥编造商品。
- **缺失字段回退：** `rewriteSignals / rewriteEvidence / rewriteRisks / rewriteAnalyses` 任何字段缺失都回退规则结果，并通过 `notices` 透传。

### 视觉识别 Prompt（`ArkRecognitionProvider`）

- 强制返回 JSON Schema：`category / brand / model / keywords / attributes / confidence / explanation`。
- 模型输出非 JSON 或缺字段时，`FallbackRecognitionProvider` 自动回退 Mock 结果，并把回退状态写回 `aiProvider` 与 `fallbackUsed`。

## 3. 鲁棒性与回退矩阵

| 场景 | 处理 |
|------|------|
| Ark 未配置（无 API Key / Endpoint） | `ArkClient.enabled=false`，调用直接抛 `IllegalStateException`，由 Fallback 拦截。 |
| Ark 返回非 JSON | `extractJsonObject` 剥离 markdown 后失败 → 回退。 |
| Ark 返回字段缺失 | 解析器逐字段判空，缺失走规则默认值。 |
| Ark 改写商品 ID | `rewriteAnalyses` 忽略 Ark productId，使用规则结果。 |
| Ark 模型超时 / 网络异常 | `RestClient` 抛异常 → 回退 + notice。 |
| 颜色识别错误 | UI 提供识别修正面板，PATCH 接口更新内存，卡片即时刷新。 |
| 文本无明确品类 | 优先继承历史识别 category，否则默认 `运动鞋`。 |
| 文本要求超出 Mock 范围 | 返回空商品 + 空比价占位，保持卡片结构稳定。 |

## 4. AI Coding 实践（团队沉淀）

### 上下文管理

- **结构化 Prompt 上下文：** 在 `ArkRecommendationExplainer.buildContext` 里只传给 Ark 当前会话相关的关键字段（keyword / maxPrice / color / preferences / signals / products），避免无关上下文污染。
- **会话粒度合并：** 用户多轮筛选条件通过 `MockAgent.MergedContext` 合并，避免每轮重新喂全量历史给 Ark。

### 约束边界

- **结构化输出 vs 自然语言：** 任何影响业务决策的字段（productId、价格、综合分）都由规则代码决定，AI 只改写文本表述。
- **白名单字段拦截：** Ark 即使试图替换 productId，也会被 `rewriteAnalyses` 强制还原，避免商品错位。
- **错误兜底：** Ark 失败时不让用户感知错误，统一通过「Provider 徽章 + notices」让评委可视化看到回退发生。

### 幻觉纠偏

- **JSON Schema 兜底：** 即便模型输出半结构化 JSON，仍能取到核心字段，缺失字段回退规则解释。
- **范围检查：** `minRating` 越界、`platforms` 包含未知平台 → 丢弃该字段，不让无效结果污染下游。
- **平台名归一化：** Ark 模型可能输出「京东」「JD.com」「jingdong」等平台别名，代码会映射到受控平台值，防止平台分类失败。当前规则解析分别支持 `京东-mock`、`拼多多-mock`、`淘宝-mock`、`天猫-mock`。

### AI 辅助编码流程

- 用 Claude Code / Trae 等 AI Coding 工具时：
  - **先给目标：** 描述要实现的能力（如「品牌/平台/排序自然语言筛选」）和约束（保留 Mock 回退、不破坏现有测试）。
  - **再给上下文：** 把 `UserPreference`、`UserPreferenceParser`、`CompositeProductSourceProvider`、`HybridRetriever`、`ResultReRanker`、`MockAgent` 现状一并提供，避免 AI 编造文件结构。
  - **测试先行：** 增加 `PreferenceExtensionTests`、`CategoryResolverTest`、`MockAgentFilterSummaryTest` 等测试，AI 改完后用 `mvn test` 回归到当前 142 条。
  - **拆任务跑：** 大改拆成「数据模型 → 解析器 → 商品源 → Agent → 解释器 → 前端 → 测试 → 文档」八步，AI 一次只关注一步。

## 5. AI 与非 AI 的边界

本项目中以下能力**不依赖** AI，以保证演示路径稳定：
- 平台名、商品 ID、价格、原价、店铺名、商品标题。
- 综合分、决策信号分数、命中偏好计数。
- 商品列表过滤、排序、分平台聚合统计、同款商品分组。
- 聊天会话/历史的内存存储与恢复。

以下能力**可选启用** AI：
- 图片识别（Ark VLM）。
- 购物意图结构化解析（Ark LLM）。
- 推荐解释面向用户的文本改写（Ark LLM）。

这种边界设计的好处：演示不会因为 AI 服务波动而失败，但只要切到 Ark 路径，AI 价值立刻可见（更细腻的解释文本、更丰富的关键属性识别），符合赛事「AI 任务编排合理、回退稳定」的评审维度。
