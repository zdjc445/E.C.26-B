# 项目分工说明

本文档梳理团队成员在本项目中的模块责任划分，便于评委在 15 分钟问答环节中针对模块直接对应到负责的同学，考察个人贡献深度。

> 注：本项目为单/多人协作均可，模块边界已按代码层次自然划分；实际作答时请按团队真实分工填写姓名。

## 答辩问答口径

评委可能从以下角度追问，团队成员需要按上面分工对应：

1. **「这个综合分怎么算的？」** → 同学 C，回答 `RecommendationExplainer.weightedScore` 的权重分配（match 25% / price 25% / reputation 20% / channel 15% / risk 15%）。
2. **「Ark 失败时怎么保证演示不挂？」** → 同学 B + 同学 C，分别说明意图解析与解释改写的回退链路与 `notices` 透传。
3. **「多轮筛选怎么记上下文？」** → 同学 A，讲解 `MockAgent.mergeContext`，按「当前明确 > 历史最新 > 默认」的覆盖规则。
4. **「品牌 / 平台 / 排序怎么从一句话里抽出来的？」** → 同学 B，演示 `UserPreferenceParser.parseBrand / parsePlatforms / parseSortBy / parseMinRating`。
5. **「Flutter 端的卡片渲染流程？」** → 同学 D，按 `_buildCard` switch 解释 5 种 cardType 渲染逻辑。
6. **「商品对比/价格走势怎么画的？」** → 同学 D，讲 `ProductItem.priceHistory` 和 `_PriceSparkline` CustomPainter。
7. **「Mock 数据为什么这么设计？」** → 同学 C + 同学 F，覆盖低/中/高三档价格、官方/非官方渠道、不同评分以支撑评分与推荐解释。
8. **「测试覆盖了什么？」** → 同学 E，按测试文件逐条说明。

## 个人贡献量化（示例）

- 每位同学应在答辩前根据 `git log` 整理自己的提交记录、PR 数量、关键改动行数。
- 推荐用以下命令导出：

```powershell
git log --author="<你的 Git 用户名>" --pretty="%h %s" --since="2026-05-20"
```

- 关键模块需准备「3 句话讲清楚我做了什么」，避免在评委追问时支吾。
