# 系统架构

## 架构原则

系统架构以 [API 接口设计](04-API接口设计.md) 为主契约，围绕以下主流程组织模块：

```text
imageId -> recognitionId -> searchTaskId -> comparisonId -> recommendationId
```

MVP 阶段使用 mock 商品数据完成闭环，后续可以替换为官方 API 或合规采集适配器，但不改变前端 API。

## 整体架构

```text
移动端 APP
  -> 后端 API 服务
    -> 用户认证与权限校验模块
    -> 图片管理模块
    -> 商品识别模块
    -> 搜索任务模块
    -> 商品归一化模块
    -> 数据源适配层
      -> mock 数据源
      -> official_api 适配器
      -> crawler 适配器
    -> 比价模块
    -> 历史价格模块
    -> 评价摘要模块
    -> Agent 推荐模块
    -> 收藏与价格提醒模块
    -> 数据库
```

## 模块划分

| 模块 | 对应 API | 职责 |
| --- | --- | --- |
| 移动端 APP | 全部 API | 注册登录、上传图片、发起识别、查看比价、展示 Agent 推荐 |
| 用户认证与权限校验模块 | `/api/auth/*` | 注册登录、Token 校验、当前用户解析、用户数据访问控制 |
| 图片管理模块 | `/api/images/*` | 上传图片、查询图片记录、删除用户图片 |
| 商品识别模块 | `/api/recognitions/*` | 基于 `imageId` 生成商品类别、品牌、关键词和置信度 |
| 搜索任务模块 | `/api/search-tasks/*` | 创建和查询搜索任务，沉淀 `searchTaskId` 作为主流程锚点 |
| 商品归一化模块 | `/api/products/*`、`/api/platform-products/*` | 将不同来源商品统一为标准商品和平台商品结构 |
| 数据源适配层 | 内部模块 | MVP 使用 mock，后续接入官方 API 或合规采集 |
| 比价模块 | `/api/comparisons/*` | 基于搜索任务候选商品生成比价结果 |
| 历史价格模块 | `/api/platform-products/{id}/price-history` | 查询平台商品历史价格与价格趋势 |
| 评价摘要模块 | `/api/platform-products/{id}/review-summary` | 汇总评价标签、风险标签和风险分 |
| Agent 推荐模块 | `/api/agent/recommendations` | 根据可信候选商品、价格、历史价格、评价摘要生成购买建议 |
| 收藏与价格提醒模块 | `/api/favorites/*`、`/api/price-alerts/*` | 管理用户收藏和价格提醒 |
| 数据库 | 所有模块 | 存储用户、图片、识别、搜索任务、商品、价格、推荐与用户私有数据 |

## 核心业务流程

```text
用户登录
  -> POST /api/images 上传图片，得到 imageId
  -> POST /api/recognitions 创建识别任务，得到 recognitionId
  -> POST /api/search-tasks 创建搜索任务，得到 searchTaskId 和候选 platformProductId
  -> POST /api/comparisons 创建比价，得到 comparisonId
  -> GET /api/platform-products/{platformProductId}/price-history 查询价格趋势
  -> GET /api/platform-products/{platformProductId}/review-summary 查询评价摘要
  -> POST /api/agent/recommendations 创建推荐，得到 recommendationId 和 evidence
  -> POST /api/favorites 或 POST /api/price-alerts 保存后续动作
```

## 数据源策略

| sourceType | 阶段 | 说明 |
| --- | --- | --- |
| mock | MVP | 使用内置样例商品、价格历史和评价摘要，保证演示稳定 |
| official_api | 后续扩展 | 通过电商开放平台或合作 API 接入真实数据 |
| crawler | 后续扩展 | 仅在合规前提下采集公开信息，需要频控、失败重试和来源标记 |

数据源适配层必须输出统一的 `platformProduct` 结构，避免前端和 Agent 直接依赖具体平台差异。

## 数据隔离原则

- 用户私有数据必须绑定 `user_id`：图片、识别记录、搜索任务、搜索结果项、比价记录、推荐记录、收藏、价格提醒
- 公共商品数据可以复用：标准商品、平台商品、价格记录、评价摘要
- 所有用户私有数据查询都必须从 access token 解析当前用户，不能信任前端传入 `userId`
- 用户访问不属于自己的资源时，优先返回 404，避免暴露资源是否存在

## 技术选型

| 层级 | 技术 | 说明 |
| --- | --- | --- |
| 移动端 | Flutter + Dart | 开发跨端 APP，优先支持 Android 演示 |
| 网络请求 | Dio | 调用后端 REST API |
| 状态管理 | Riverpod | 管理登录态、搜索任务、比价结果和推荐结果 |
| 图表 | fl_chart | 展示历史价格趋势 |
| 后端 | Spring Boot 4 + Java 21 | 提供 REST API、业务流程编排和模块化服务 |
| 鉴权 | Spring Security + JWT | 实现 access token、refresh token 和接口权限控制 |
| 数据库 | PostgreSQL | 存储用户、商品、搜索任务、价格历史和推荐证据 |
| ORM | Spring Data JPA | 管理实体、Repository 和事务 |
| 数据库迁移 | Flyway | 管理 schema 版本和初始化数据 |
| API 文档 | springdoc-openapi | 生成 OpenAPI 文档，支撑前后端契约开发 |
| 图片存储 | 本地 `uploads/` 目录 | MVP 阶段保存用户上传图片，后续可替换为对象存储 |
| 商品数据源 | MockProductSourceProvider | MVP 使用 mock 商品、价格历史和评价摘要 |
| AI 识别 | MockRecognitionProvider | MVP 模拟图片识别结果，后续替换为多模态模型 |
| Agent 推荐 | RuleBasedRecommendationService | MVP 基于规则和 evidence 生成推荐，后续可接入大模型 |

## 技术边界

MVP 阶段暂不实现：

- 真实电商平台 API 接入
- 大规模真实爬虫
- 自动购买
- 真实价格提醒通知调度
- 真实多模态模型调用

MVP 目标是先跑通稳定闭环，再替换数据源和 AI 能力。
